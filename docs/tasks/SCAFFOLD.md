# Task: Scaffold the 3H1L Frontend

## Objective

Set up the frontend foundation for the Three Headlines and a Lie (3H1L) application in `web/`.

The goal is a working, lint-clean Next.js project configured for static deployment, ready for game implementation in a subsequent task.

**This task is scaffolding only. Do not implement game functionality or edit the root README.**

## Instructions and Context

Before starting, read:

- Repository-root `AGENTS.md`
- `web/AGENTS.md`
- `docs/project_spec.md`

Follow their instructions and technical decisions.

Inspect the existing repository and `web/` directory before making changes. The directory structure and application dataset may already exist; preserve existing work.

The Python/ML project at the repository root is complete and must remain untouched. In particular, do not modify Python dependencies, `uv.lock`, notebooks, ingestion scripts, datasets or trained models.

## Requirements

### 1. Initialise Next.js

Set up a current stable Next.js application in `web/` with:

- TypeScript
- App Router
- `src/` directory
- ESLint
- Tailwind CSS
- `@/*` import alias
- npm as the package manager

Use idiomatic defaults and avoid unnecessary dependencies.

If the existing directory prevents safe initialisation, do not overwrite or delete files. Use a temporary sibling directory and merge only non-conflicting scaffold files, explaining any conflicts.

### 2. Configure static export

Configure Next.js for static export using `output: 'export'`.

Do not introduce API routes, a backend, server-side inference, authentication or a database.

### 3. Preserve the application data

Preserve `web/public/data/quizzes.json` exactly as it exists.

Do not regenerate, reorder, reformat or otherwise modify the quiz dataset.

The frontend must remain independent of the root `data/` and `models/` directories at runtime.

### 4. Configure Git ignore rules

Inspect the existing root `.gitignore` before modifying it.

Ensure frontend-generated files and dependencies are ignored where appropriate, including:

- `web/node_modules/`
- `web/.next/`
- `web/out/`

Do not ignore `web/public/data/quizzes.json` or other frontend source files.

Avoid unrelated changes to existing ignore rules.

### 5. Keep the scaffold minimal

Generate the standard files required for a functioning Next.js project.

A minimal placeholder homepage is acceptable. Do not implement the game, results screen, model comparison, animations, game logic or additional application components.

Do not create testing frameworks, browser tests or CI workflows in this task. Those belong to later tasks.

## Decisions Log

### Inspection findings (pre-work)

- `web/` had empty subdirectories (`src/app`, `src/components`, `src/lib`, `src/types`, `e2e`, `tests`) and `AGENTS.md` only. No Next.js config files or `package.json` existed.
- The quiz dataset exists at `web/public/data/app_quizzes.json`. The root `AGENTS.md` refers to it as `quizzes.json` but the actual file is `app_quizzes.json`. Preserved as-is; the correct filename will be referenced in the game implementation task.
- `web/src/data/model_results.json` already existed with model evaluation results. Preserved unchanged.
- Node.js v24.16.0, npm 11.13.0 available. Latest stable Next.js is 16.4.2.

### Next.js initialisation

- Used `create-next-app@16.4.2` with `--typescript --eslint --tailwind --app --src-dir --import-alias "@/*" --use-npm --no-git --no-agents-md --skip-install`. Scaffolded into a temp `web-tmp/` directory (because `create-next-app` refuses to run into a non-empty directory), then merged config files into `web/`, followed by `npm install` in `web/`. The temp directory was removed after merging.
- `--no-agents-md` used to prevent `create-next-app` from overwriting the project's existing `web/AGENTS.md`.
- `package.json` name corrected from `web-tmp` (temp directory artefact) to `three-headlines-and-a-lie`.

### Static export configuration

- `output: "export"` added to `next.config.ts`.
- `partialPrefetching: true` and `cacheComponents: true` (both generated by default in Next.js 16) were removed. Both options enable PPR (Partial Pre-Rendering), which requires a server runtime and is incompatible with `output: "export"`. The build error `Invariant: PPR cannot be enabled in export mode` confirmed this.

### Git ignore

- `web/.gitignore` generated by `create-next-app` already covers `node_modules/`, `.next/`, and `out/` with paths relative to `web/`. No changes to the root `.gitignore` were needed; these entries are correctly scoped to the frontend subdirectory.

### ESLint deprecation warning

- `npm install` and `npm run lint` emit `npm warn deprecated eslint@9.39.5`. This is a transitive dependency of `eslint-config-next` and is not within the scope of this scaffolding task to resolve.

### Audit vulnerabilities

- `npm audit` reports 5 high severity vulnerabilities in the installed dependency tree. These are from `create-next-app`'s own dependency choices. Running `npm audit fix --force` could introduce breaking changes and is out of scope for this task.
