# Three Headlines and a Lie (3H1L)

## Requirements

This project builds a playable web app based on Morning Brew's "Three Headlines and a Lie" newsletter format. Players are shown four headlines and must identify the fabricated one.

The project is a portfolio piece demonstrating end-to-end data science and software development, including data acquisition, machine learning experimentation, model evaluation, frontend development, testing and deployment.

The application should allow players to:

- Start a game consisting of shuffled quiz questions, without repeating questions within a game.
- Select one of four headlines and receive immediate feedback.
- See the correct answer, relevant source/GIF links and their running score.
- Finish after answering at least 10 questions, or continue until all 67 questions have been answered.
- View their final accuracy alongside the fixed evaluation results of the ML models, with appropriate caveats.
- Start a new game with a fresh shuffle.

The UI should be polished, responsive, intuitive and fast. The intended experience is a small, finished game rather than a generic ML dashboard.

## Limitations

This is a deliberately lightweight, frontend-only MVP (all backend ingestion scripts and ML notebooks should be left untouched).

- No backend, database, authentication, user accounts, API calls or server-side ML inference.
- Scores are local to the current game session. There is no shared leaderboard or central collection of player results.
- The answer key is inspectable because the application is statically hosted and its data is downloaded by the browser. This is an accepted limitation.
- The ML results are fixed evaluation data, not predictions generated by the application.
- The test set contains only 67 quizzes. Model accuracy estimates are uncertain, and a player's score over a subset of questions is not directly comparable with model accuracy measured across all 67 questions.
- Do not introduce extra features or infrastructure unless explicitly requested.

## Technical Decisions

- **Frontend:** Next.js with TypeScript and the App Router.
- **Styling:** Tailwind CSS, unless the existing frontend implementation provides a compelling reason to use an alternative.
- **Hosting:** Vercel, using Next.js static export (`output: 'export'`).
- **Frontend location:** `web/`, with its own Node.js dependencies and configuration.
- **Quiz data:** `web/public/data/quizzes.json`, containing the curated 67-question application dataset.
- **Model results:** A separate frontend-owned file, such as `web/src/data/model-results.json`.
- **Python environment:** Continue using `uv` for the existing Python project. Do not merge the Python and Node.js environments.
- **Testing and CI:** Include proportionate automated tests, linting, TypeScript checks and production-build validation. Add a browser end-to-end test and GitHub Actions CI where practical.

Keep all game functionality client-side. Do not add AWS, Docker, a backend or other hosting infrastructure without an explicit change in requirements.

## Starting Point

The existing repository contains the completed data acquisition, data preparation, modelling and evaluation work.

The root Python project includes its own environment configuration, scripts, notebooks and local datasets/model artefacts. The root `.gitignore` excludes the local `data/` and `models/` directories.

The curated application dataset has been created separately under `web/public/data/quizzes.json`. The quiz records contain IDs, dates, four headline objects with text and URLs, and a zero-based answer index.

The established ordering of the four headlines within each quiz must be preserved. Shuffle the order of quizzes between games, not the individual headline options.

The application must depend only on its tracked frontend assets and must not require access to the ignored root `data/` or `models/` directories at runtime.

Inspect the actual repository before making changes. Preserve existing work, particularly application data and configuration, rather than overwriting files or regenerating the project unnecessarily.
